# Explicit assumptions and limitations

## From the assessment sources
Only the supplied Veridian policies/requests/queue are business evidence. The week is
21-25 September 2026. Ten KB entries plus one Asset extract are supplied. All 15 requests
and four open queue tickets need handling; six closed queue tickets are context only.
The source requires understanding, retrieval, clarification, simple resolution, safe
escalation, structured tickets, citations and auditability. It does not require a paid
host, vector database, real email delivery or a specific programming framework.

## Application choices, not company policy
- A signup creates a demo-operator identity and a separate seeded fictional workspace.
- Queue labels IT_FINANCE/MANAGER_FINANCE and all normalized status enums are implementation
  conventions; the data does not give a complete organizational routing directory.
- IT review for an unsupported admin request is a safe fallback, not a discovered access policy.
- IT assessment for a flickering laptop is a conservative route, not a specified repair SOP.
- Password minimum length, session lifetime, rate limits and UI colours are prototype choices.
- Source data is an all-data exercise snapshot, not an as-of-current-day feed or an SLA model.
- ASSET-01 is a local citation ID assigned to the unnumbered Asset Management extract.
- Punctuation/whitespace normalization does not claim to change source policy meaning.

## Deliberately not assumed
No precedence between the laptop documents; no verified hardware failure; no completed
manager/Finance/Security approvals unless actually supplied; no actual approved catalog,
renewal portal/form URLs, allowance amount, assigned approver name, current mailbox usage,
exact review deadline, missing queue-ticket dates/email addresses or external system access.

## What the application actually executes
It reads PostgreSQL policy/case data; classifies language via Gemini or labelled fallback;
calculates a policy decision; persists messages, facts, local service tickets and audits.
It does NOT unlock corporate accounts, approve replacement, provision VPN/admin rights,
ship equipment or send real Security emails. A local handoff is not completed IT service.

## Security and intelligence limits
Local signup is not verified corporate identity. No email verification/recovery system is
claimed. Exact evidence quotes reduce unsupported extraction but cannot mathematically prove
semantic correctness. Keyword fallback has limited language coverage. Audit is append-only
at the application/ordinary-SQL level, not immune to a malicious database administrator.
Production SSO, real approvals, operational integrations and independent security assessment
would be separate work; do not describe this prototype as production-complete.
